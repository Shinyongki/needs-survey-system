# 현장설문 결과보고서 docx 생성 가이드

> 목적: 15개 사업 현장설문 결과보고서를 일관된 품질로 생성하기 위한 구현 명세
> 기준 문서: J17 종사자지원사업 결과보고서 v8.1 (확정 완성본)
> 적용 대상: docx 생성 스크립트 (Node.js docx 라이브러리)
> 작성일: 2026-04-10

---

## 1. 핵심 원칙

- 이 가이드는 **분석지시어(설계)**와 **docx 스크립트(구현)** 사이의 간극을 없애기 위한 문서이다
- 분석지시어 v8의 모든 지시를 docx에 빠짐없이 반영해야 하며, "간소화"는 허용하지 않는다
- 각 장의 필수 요소를 하나라도 누락하면 불완전한 보고서이다
- 서술식 문장은 개조식이 아닌 완결 문장이며, 사업담당자가 결과보고서에 그대로 복사 가능해야 한다

## 3. 장별 필수 요소

### I. 조사 개요

**구성요소:**
- 2열 표 (항목 / 내용)
- 항목 열: 배경색 #E8F0F8

**필수 행:**

| 항목명 | 내용 예시 |
|---|---|
| 사업명 | 종사자 지원사업 |
| 응답 대상 | 전담사회복지사 (또는 생활지원사) |
| 조사 방법 | 구글 폼 (온라인 자기기입식) |
| 응답 인원 | ○○명 |
| 척도 방향 | 1=매우 그렇지 않다 ~ 5=매우 그렇다 (높을수록 좋음) |
| 긍정 응답 기준 | 4+5 합산 / 부정 응답: 1+2 합산 |

> 문항 구성은 별도 표시하지 않는다 (J17 기준).

---

### II. 이 사업의 분석 관점

**필수 구성요소 3가지:**

**① 분석 관점 박스** (배경 #F0F4F8, 테두리 #1B4F72)
- 광역의 역할 설명 (1~2문장)
- 핵심 질문 (따옴표로 강조)
- 문항 간 경로 구조 명시 (경로 1, 경로 2 등)
- 사업 고유 분류 체계가 있으면 포함 (예: J17의 4가지 지원 유형)

**② 경로 구조도 차트** (matplotlib 생성, 이미지 삽입)
- 문항 간 논리적 흐름을 시각적으로 표현
- 화살표로 전제→결과 관계 표시
- 사업 패턴에 따라 형태가 달라짐:
  - 프로세스형(J01): 단계별 순차 흐름
  - 2요소형(J07): 두 요소 병렬 + 합류
  - 갭형(J08·J11): 응대↔해결 대비 구조
  - 경로형(J17): 경로 1·경로 2 분기 후 합류
  - 4차원형(J09): 4축 레이더 구조

**③ 본문 서술** (박스 아래)
- 분석 관점을 풀어서 설명하는 2~3개 문단
- 박스 내용을 반복하지 않고, 해석의 틀을 설명

---

### III. 만족도 분석

**필수 구성요소 5가지:**

**① 공통·특화 분리 표**
- 공통 4문항 표와 특화 문항 표를 **별도로** 작성
- 컬럼: 문항 | 평균 | 긍정(4+5) | 부정(1+2) | **판정**
- 판정 기준:
  - 긍정 70% 이상 → **양호** (초록)
  - 긍정 50~69% → **보통** (파랑)
  - 긍정 50% 미만 또는 부정 15% 이상 → **주의** (빨강)

> 주의: J17 기준에는 1~5점 빈도 분포가 없다. 요약형 표(평균·긍정·부정·판정)를 사용한다.
> 단, 빈도 분포가 필요한 경우(특정 문항 해석에 분포가 중요할 때) 별도 표로 추가할 수 있다.

**② 만족도 서술** (서술식 문장)
- 종합 만족도 → 최고 항목 → 최저 항목 → 전체 해석 순서
- 3~5개 완결 문장
- 구체적 수치(평균·긍정비율·부정비율) 필수 포함
- "○명 중 1명 이상이" 같은 체감 표현 사용

**③ 긍정비율 수평 막대 차트**
- 전 문항의 긍정비율을 한눈에 비교
- 양호(70%↑)=초록, 보통=파랑, 주의(50%↓)=주황/빨강

**④ 레이더(균형 프로파일) 차트**
- 공통 4문항 + 특화 문항 전체를 방사형으로 표현
- 함몰 영역이 약점

**⑤ 레이더 해석 서술** (1~2문장)
- 함몰 영역과 돌출 영역을 문장으로 설명

---

### IV. 고유 분석

**이 장은 사업마다 분석 방법이 다르다.** 분석지시어 v8의 "고유 분석 지시"를 그대로 따른다.

**공통 필수 요소:**

**① 경로별 갭 표** (전제→결과 구조)

| 전제 조건 | 평균 | → | 결과 항목 | 평균 | 갭 |
|---|---|---|---|---|---|

- 경로가 여러 개이면 경로별로 표를 분리
- 갭이 0.3점 이상이면 ⚠️ 표시

**② 교차분석 (조건부 평균 비교)**
- 전제 문항의 부정 응답자(1~2점)와 긍정 응답자(4~5점)를 나누어, 결과 문항의 평균을 비교
- 예: "사전안내 부정(1~2점) 16명의 내용이해 평균 1.62점 vs 긍정(4~5점) 24명의 평균 4.17점"
- 이 분석이 **인과관계 해석**의 핵심 근거가 된다
- 교차분석 결과를 **차트로 시각화** (그룹 막대 또는 비교 막대)

**③ 갭 해석 서술** (인과관계까지)
- 단순 "갭이 ○○점이다"가 아니라, **왜 그 갭이 발생하는지**, **무엇을 바꾸면 해소되는지**까지 서술
- 이탤릭 인용 블록으로 핵심 해석 강조 (예: "사람은 좋은데 시스템이 나쁜 구조이다")

**④ 고유 분석 차트** (사업 패턴에 따라)
- 프로세스형: 단계별 꺾은선 + 단절 지점 표시
- 2요소형: 두 요소 비교 막대
- 갭형: 응대 vs 해결 비교 + J08·J11 교차 비교
- 4차원형: 4축 레이더 + 최저축 강조
- 단일선택 문항: 항목별 빈도 수평 막대

### V. 주관식 분석

**필수 구성요소 3가지:**

**① 사업 고유 분류 체계로 분류**
- 분석지시어에 명시된 분류 기준 사용 (사업마다 다름)
- 분류별 건수·비율 제시

**② 유형별 상세 서술**
- 각 분류별로 소제목 + 2~3문장 서술
- 해당 유형의 핵심 키워드와 건수 명시
- IV장의 갭 분석 결과와 연결 ("경로 1의 약점과 직접 연결된다" 등)

**③ 키워드 순위 표**

| 순위 | 키워드 | 건수 | 관련 유형 |
|---|---|---|---|

- Top 5~7 키워드
- 키워드 분류 차트 (수평 막대) 포함

### VI. 통합설문 이행 확인

**필수 구성요소 4가지:**

**① 도입 서술** (1~2문장)
- "상반기 통합설문(섹션 ○○)에서 파악된 욕구가 이번 회차에서 개선되었는지 확인한다"
- "새로운 욕구를 수집하는 것이 아니라, 이행 여부를 점검하는 성과 환류이다"

**② 이행 확인 차트** (matplotlib)
- 통합설문 욕구 → 현장설문 결과를 시각적으로 연결
- 화살표 또는 비교 막대

**③ 이행 확인 표**

| 통합설문 욕구 | 통합설문 수치 | 현장설문 결과 | 이행 판정 |
|---|---|---|---|

- **통합설문 수치 컬럼 필수** — 인수인계 문서 7절의 수치를 그대로 사용
- 판정: 개선(초록) / 미개선(빨강) / 양호 유지(파랑)

**④ 이행 확인 서술** (3~5문장)
- 전체 이행 결과 요약
- 미개선 항목의 원인 추정
- 구조적 문제와 개인 역량을 구분하는 해석
- 이탤릭 인용 블록으로 핵심 메시지 강조

### VII. 이번 회차 개선 과제

**필수 구성요소 4가지:**

**① 도입 서술** (1~2문장)
- "이번 회차 결과에서 드러난 문제를 다음 회차에 반영하는 사후 환류이다"

**② 과제별 구조화 표** (과제 1개당 1개 표)

| 항목 | 이번 결과 | 문제 | 다음 회차 보완 방향 |
|---|---|---|---|

- 과제 수: 2~4개
- 각 과제에 소제목 부여 (예: "과제 1. 안내 시기·방식 개선 (경로 1 보완)")
- 표 아래에 근거 서술 (주관식 키워드 연결 포함)

**③ 개선 과제 요약 박스** (배경 #FFF8E1, 테두리 #E65100)
- 과제 1~3을 한줄씩 요약
- 각 과제에 근거 수치와 주관식 키워드 병기
- 마지막 줄: "※ 이 과제는 사후 환류이며, 연간 사업 방향은 통합설문 욕구에 따른다"

**④ 사후 환류 주석** (박스 밖)
- "※ 위 개선 과제는 이번 회차 결과에서 도출한 사후 환류 과제이며, 연간 사업 방향은 통합설문 욕구조사 결과에 따라 수립한다."

### IX. 근거문장

**구성: 4~5개 근거문장, 유형별 소제목**

**필수 유형:**

| 유형 | 소제목 예시 | 내용 |
|---|---|---|
| 만족도 기반 | "만족도 기반 (지속 근거)" | 종합만족도 + 강점 항목 → 지속 운영 근거 |
| 약점 개선 | "○○ 개선 (경로 ○ 근거)" | 갭 분석 결과 → 개선 추진 근거 |
| 통합설문 이행 | "통합설문 이행 확인 기반 (구조적 근거)" | 통합설문 수치 + 현장설문 결과 → 미개선 시 재설계 근거 |
| 사후 환류 | "사후 환류 과제 기반" | 이번 회차 부정비율 + 주관식 → 다음 회차 적용 근거 |

**근거문장 작성 규칙:**
- ◆ 기호로 시작
- 굵은 글씨 + 인용 블록 형식
- 문항번호 대신 한글 직접 인용: "(종합 만족도, 응대 신속성)"
- 통합설문과 현장설문을 명확히 구분: "(통합설문 사전 안내 충분성 / 현장설문 사전 안내 충분성)"
- 구체적 수치(비율·평균·갭) 반드시 포함

  data: fs.readFileSync(path),
  transformation: { width: w, height: h }
})

## 5. 분석 코드 필수 항목

### 5-1. 기본 분석 (전 사업 공통)

| 분석 | 산출 항목 |
|---|---|
| 기술통계 | 문항별 빈도·비율·평균·긍정비율·부정비율 |
| 판정 | 양호/보통/주의 자동 판정 |
| 갭 분석 | 경로별 전제→결과 갭 산출 |
| 교차분석 | 전제 문항 부정(1~2)·긍정(4~5) 그룹별 결과 문항 평균 |
| 주관식 | 키워드 추출, 사업 고유 분류, Top 5~7 순위 |

- 이행 확인 표의 "통합설문 수치" 컬럼에 직접 사용

## 6. 검증 체크리스트

각 보고서 생성 후 아래 항목을 확인한다.

### 구조 검증

- [ ] 표지 페이지가 있는가 (J코드·사업명·응답대상·인원·기관명·연도)
- [ ] I~IX장 순서가 정확한가
- [ ] 각 장 시작 전 페이지 브레이크가 적절한가

### II장 검증

- [ ] 분석 관점 박스가 있는가 (핵심 질문·경로 구조·광역 역할)
- [ ] 경로 구조도 차트가 삽입되어 있는가
- [ ] 본문 서술이 박스 아래에 있는가

### III장 검증

- [ ] 공통·특화 문항 표가 **분리**되어 있는가
- [ ] 표에 **판정 컬럼**이 있는가 (양호/보통/주의)
- [ ] 만족도 서술이 완결 문장인가 (3~5문장)
- [ ] 긍정비율 수평 막대 차트가 있는가
- [ ] 레이더 차트가 있는가
- [ ] 레이더 해석 서술이 있는가

### IV장 검증

- [ ] 경로별 갭 표가 **전제→결과 구조**인가
- [ ] **교차분석**(조건부 평균)이 포함되어 있는가
- [ ] 교차분석 차트가 있는가
- [ ] 갭 해석이 **인과관계까지** 서술되어 있는가
- [ ] 이탤릭 인용 블록으로 핵심 해석이 강조되어 있는가
- [ ] 고유 분석 차트가 있는가

### V장 검증

- [ ] 사업 고유 분류 체계로 분류되어 있는가
- [ ] 분류별 소제목 + 상세 서술이 있는가
- [ ] 키워드 순위 표가 있는가 (순위·키워드·건수·관련유형)
- [ ] 키워드 분류 차트가 있는가

### VI장 검증

- [ ] 도입 서술에 "이행 여부 점검"과 "새 욕구 수집이 아님"이 명시되어 있는가
- [ ] 이행 확인 차트가 있는가
- [ ] 이행 확인 표에 **통합설문 수치 컬럼**이 있는가
- [ ] 이행 판정(개선/미개선)이 색상으로 구분되어 있는가
- [ ] 이행 확인 서술이 있는가 (3~5문장, 인과 해석 포함)

### VII장 검증

- [ ] 과제별 **구조화 표**(항목/결과/문제/방향)가 있는가
- [ ] 각 과제에 소제목이 있는가
- [ ] 과제별 서술에 주관식 키워드가 근거로 연결되어 있는가
- [ ] **개선 과제 요약 박스**가 있는가
- [ ] 사후 환류 주석이 있는가

### VIII장 검증

- [ ] 요약 박스에 태그 형식([만족도][강점][약점][경로][이행확인][개선과제][주관식])이 있는가

### IX장 검증

- [ ] 4~5개 근거문장이 있는가
- [ ] 유형별 소제목이 있는가 (만족도 기반 / 약점 개선 / 이행 확인 / 사후 환류)
- [ ] ◆ 기호 + 굵은 인용 블록 형식인가
- [ ] 문항번호 대신 한글 직접 인용 괄호인가
- [ ] 통합설문과 현장설문 출처가 구분되어 있는가

### 금지어 검증

- [ ] "경영평가" 사용되지 않았는가
- [ ] 析(한자) 사용되지 않았는가
- [ ] 영어 약자(SW, IPA 등) 사용되지 않았는가
- [ ] 문항번호 괄호(공통-1, A-2 등)가 근거문장에 사용되지 않았는가

## 8. 작업 절차 요약

```
1단계: 분석지시어에서 해당 사업의 고유 분석 관점·경로·특화문항 확인
2단계: mock 데이터 생성 (사업 특성에 맞는 분포 설계)
3단계: 분석 실행
  - 기술통계 + 판정
  - 갭 분석 (경로별)
  - 교차분석 (조건부 평균)
  - 주관식 키워드 + 사업 고유 분류
4단계: 차트 생성 (7종 필수)
  - II장 경로 구조도
  - III장 긍정비율 막대 + 레이더
  - IV장 고유분석 차트 + 교차분석 차트
  - V장 키워드 분류 막대
  - VI장 이행 확인 비교 차트
5단계: docx 생성 (이 가이드의 3장 필수 요소 전부 포함)
6단계: 검증 (이 가이드의 6장 체크리스트)
7단계: outputs 폴더 복사 + present_files
```
