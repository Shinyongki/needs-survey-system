## 🔍 검증 프레임워크

### 검증 축 1: 문항 번호·필드명 일관성

**검증 대상**
- 설문 파일(A)의 문항 번호 ↔ 분석지시어(B)의 참조 코드
- 분석지시어(B)의 코드 ↔ 구글폼 Apps Script(E)의 헤더매핑
- Apps Script(E)의 헤더매핑 ↔ 지시문 06(D)의 CSV 파싱 로직

**필수 일치 사항**
- `기본-00` (통합설문 소속 기관)
- `기본-0`, `기본-1` (통합설문 연령대·경력)
- `도입-0` (현장설문 소속 기관)
- `도입-0-a` (현장설문 회차)
- `도입-1`, `도입-2` (현장설문 연령대·경력)

## 🚨 예상 불일치 지점 (사전 예측)

### 높은 가능성 (선제 확인 필요)

**1. 세션 B의 기관별 분석 섹션에서 참조하는 ID 형식**
- 지시문 06 v1 작성 시점엔 `institution_id (int)` 방식이었음
- v2에서 `institution_code (text)` 로 변경됨
- 세션 B가 v1 기준으로 작성했을 가능성 존재 → SQL 예시 수정 필요 가능

**2. 세션 C의 계획안 "구글폼 17종" 반영**
- 계획안.md 기존 336행 "구글폼 18종" 오류가 수정되었는지 확인
- 읽기전용 파일이었으므로 업로드 과정에서 교체가 정상 완료되었는지 확인

**3. Apps Script의 회차 초기값**
- `config.gs`의 `INITIAL_ROUNDS`가 현장설문.md의 회차 표기 예시와 정확히 일치하는지
- 용기가 운영 중 추가할 회차와의 일관성을 위해 템플릿 확정 필요

**4. 척도 방향 명시 누락**
- 설문 파일(A)에 "CSV는 1=부정, 5=긍정으로 저장" 주석이 있는지
- 없으면 세션 B 분석지시어나 결과보고서에서 혼란 가능

### 중간 가능성

**5. 현장설문 15종 도입부 문항 수 계산**
- A(설문)와 Apps Script(E)의 각 J코드 문항 수가 정확히 일치하는지
- 특히 J01(13), J06(13), J09(13)처럼 다문항 사업에서 오류 가능성

**6. header_mapping 시트 내부 코드 명명 규칙**
- `공통-1` vs `common-1` vs `Q5` 중 어느 형식인지
- Apps Script·지시문 06·분석지시어 3자가 일치해야 함

### 낮은 가능성 (일상 체크)

**7. 권역·시군구 표기**
- `중부(창원·함안·의령·창녕)` 형식 일관성
- 시군구 가나다순 정렬 일치

**8. 용어 통일**
- 각 세션이 공통 요약 문서를 참조했으므로 용어는 대체로 일치할 것
- 다만 영문 약어(SW, CSI, IPA 등)의 한글 병기 여부는 편차 있을 수 있음

## 🔍 비판적 검토자 노트

**통합 검증 세션 자체의 한계**

- 검증 세션이 모든 불일치를 발견할 수 있다는 보장은 없음
- 실제 시스템 구현(Claude Code 세션)에서 발견되는 문제도 있을 것
- 따라서 **검증 세션 = 완벽한 품질 보증**이 아니라 **주요 불일치 선제 발견** 정도로 기대치 설정
