## 2. 확정된 보고서 구조 (9장)

모든 보고서는 아래 9장 구조를 따르며, **J17 수준의 깊이**를 유지해야 합니다.

| 장 | 명칭 | 핵심 포인트 |
|---|---|---|
| I | 조사 개요 | 표 형태, 6행 |
| II | 이 사업의 분석 관점 | 좌측 강조선 박스 + 경로 구조도 차트 + 본문 서술 |
| III | 만족도 분석 | 공통·특화 분리 표 + **서술식 3~5문장** + 긍정비율 막대 + 레이더 |
| IV | 고유 분석 | **갭 표(전제→결과)** + **교차분석(인원수·점수·차이 명시)** + 이탤릭 인용 블록 |
| V | 주관식 분석 | **유형별 소제목 + 건수 + 키워드 + 해석 2~3문장** + **Top 7 표(4열)** |
| VI | 통합설문 이행 확인 | 4건 이행 표 + **항목별 상세 서술** + 구조/개인 구분 해석 + **이탤릭 인용 블록** |
| VII | 개선 과제 | **3개 과제** × **4열 구조화 표** + **표 아래 근거 서술** + 요약 박스 |
| VIII | 요약 | 태그 형식 요약 박스 |
| IX | 근거문장 | 5개 근거문장 (만족도/약점/경로/이행/사후환류) |

### V·VI·VII장 깊이 기준 (J17 수준)

**V장 — 주관식:**
- 사업 고유 분류 체계(4~5유형)별 **소제목 + 건수 + 핵심 키워드(건수 포함) + 해석 2~3문장**
- 각 유형에서 IV장 갭 분석 결과와 연결 ("경로의 약점과 직접 연결된다")
- **키워드 Top 7 표** (순위 | 키워드 | 건수 | 관련 유형)

**VI장 — 이행 확인:**
- 이행 확인 항목 **4건**
- 각 항목별 **상세 서술 문장** (왜 이행/미개선인지 원인 해석)
- 구조적 문제와 개인 역량을 **구분하는 해석** 문단
- **이탤릭 인용 블록**으로 핵심 메시지 강조

**VII장 — 개선 과제:**
- 과제 **3개**, 각각에 **4열 구조화 표** (항목 | 이번 결과 | 문제 | 다음 회차 보완 방향)
- 표 아래 **근거 서술** — 교차분석 수치 + 주관식 키워드 건수 직접 인용
- **개선 과제 요약 박스** — 과제별 근거 수치와 주관식 키워드 병기

## 5. 작업 절차

```
각 사업별로 아래 순서로 진행합니다.

1단계: 데이터 보강 (Python — j[코드]_enrich.py)
  - mock CSV 로드 → 교차분석 구체화 (인원수·점수·차이)
  - 주관식 상세 분류 (4~5유형 × 소제목+건수+키워드+해석)
  - 키워드 Top 7 (순위·키워드·건수·관련유형)
  - 이행 확인 4건 (각 항목별 상세 서술 포함)
  - 개선 과제 3개 (4열 구조화 표 + 근거 서술)
  - → j[코드]_analysis.json 저장

2단계: 차트 생성 (Python — chart_style.py 모듈 사용)
  - figsize: FLOW(16,5) / WIDE(14,6) / MEDIUM(12,6) / RADAR(10,10) / KEYWORD(12,5)
  - 내부 폰트: 기본 13pt, 라벨 14~15pt, 제목 18pt
  - → charts_j[코드]/ 에 7종 저장

3단계: docx 생성 (Node.js — docx_builder.js 모듈 사용)
  - 장 사이 PageBreak 없음 → spacer(500)으로 구분
  - 차트 삽입 크기: WIDE(660×310) / RADAR(500×500) / FLOW(660×230) 등
  - 박스: 좌측 강조선 스타일 (accentBox)
  - 근거문장: evidenceBox
  - → /mnt/user-data/outputs/ 에 저장

4단계: 검증
  - validate.py 통과
  - 금지어 0건 (경영평가, 析, SW, IPA)
```

## 6. 기술 스택 및 핵심 규칙

### 도구
- **Python**: mock 데이터 생성, 분석, 차트 (matplotlib)
- **Node.js**: docx 라이브러리로 Word 문서 생성
- **한글 폰트**: `/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc`

### 공통 모듈
- **chart_style.py**: matplotlib 스타일, 색상 팔레트, figsize 상수, styled_bar_h, styled_radar 함수
- **docx_builder.js**: 표지, 표, 박스, 차트삽입, 근거문장 등 공통 함수, saveAndFix(pBdr 순서 자동 수정)

### 색상 팔레트
```
BLUE = '#2E5C8A'  (메인/표 헤더)
DARK = '#1B4F72'  (제목)
LIGHT = '#5B9BD5'  (보조)
ORANGE = '#ED7D31'  (주의)
RED = '#E74C3C'  (경고/미개선)
GREEN = '#27AE60'  (양호/개선)
```

### 핵심 규칙
- **"경영평가" 용어 사용 금지** → "사업 운영 근거 확보"
- **析 한자 금지** → "분석" 한글만
- **영어 약자 금지** → 한글 전체 표기 (SW→전담사회복지사, IPA→중요도-만족도 분석)
- **문항번호 괄호 금지** → 한글 직접 인용 ("(종합 만족도, 응대 신속성)")
- **근거문장 형식**: "○○조사 결과 ○○%가 ○○을 요청하여 ○○을 추진한다."
- **docx ImageRun**: `type: "png"` 필수 명시
